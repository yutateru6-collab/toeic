# 問題の編集・校閲・更新

初回リリースは作成者による見直しとデータ整合性チェックを行った90問の試作版。独立した専門家の承認済み教材ではありません。自動テストが文法的正確さや本番難易度を保証することはありません。

1. `src/questions.ts`の1行が1問。区切りは`|`、選択肢・理由の区切りは`~`。配列内の順序でIDが決まるため、既存行の並びを変更しない。
2. 正解番号は原稿の0始まりの番号。画面では固定の回転を行い、選択肢と理由を同時に移動する。
3. 修正時は公開後の問題versionを上げる。大幅な論点変更は新しい問題IDとして扱い、以前の成績との比較を行わない。
4. 問題文に4候補をすべて入れて解き直し、辞書・語法・意味で各誤答が不適切な根拠を確認する。別解・自然な読み方が残った場合は公開問題から外し、件数表示とテストも更新する。
5. 日本語訳と解説の整合性を確認。文法上入りうるが文脈に合わない語を「文法的に絶対不可」と説明しない。
6. 語数・構文・選択肢型・主論点・判断範囲を公式資料の分析と照合する。難語を増やすだけで難問にしない。
7. `pnpm test`と`pnpm build`を通し、スマホで当該問と解説を読む。
8. Gitの変更をレビューし、`main`に反映。Cloudflareのビルドと公開結果を確認する。

現行familyは各問ID。出題論点の一致と、実質的に同じ問題の一致は区別する。今後テンプレート類題を追加する場合は同一familyを付け、練習と評価をまたがせない。現行の固定30問による成績は標準化テストではない。

## 本番レベルを検証する次工程

正規に利用できる公式問題集の本文を確保し、10回分300問の分析に進む。出題比率・語数分布・実測正答率を推測で埋めない。新規問題を独立校閲し、初見回答者の正答率・選択肢選択率・時間と公式基準課題の結果を比較する。確認数と対象集団を明記する。
